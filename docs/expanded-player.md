# 展开播放器

点击底部播放栏的封面进入展开页，参考 [Apple Music 播放器](https://support.apple.com/guide/music/use-music-miniplayer-mus71d7dcfce/mac) 的大封面与播放控制布局，使用项目现有 shadcn 主题色、按钮、边框、圆角及浮层。

## 功能与布局

- 桌面左侧展示封面、标题、创作者、专辑、进度和播放控制，右侧展示歌词；窄屏可通过顶部歌词按钮切换封面与歌词，保留播放控制。顶部队列按钮在所有屏幕尺寸打开右侧浮窗，不挤压主内容。浮窗直接复用 `PlayQueue`，原侧栏与浮窗共享 `QueueTracks`、列表间距、顶部留白和队列操作。原生 Popover 负责点击外部 / Esc 关闭。
- 支持播放 / 暂停、上一首 / 下一首、播放模式、拖动与键盘跳转进度、音量 / 静音、音质选择、播放错误及重试。
- 歌词区不显示额外的「歌词」标题；有翻译时，在展开页顶部队列按钮旁显示「译」开关，桌面和窄屏共用，切换不重新请求歌词。顶部左右操作区预留同等宽度，让中间的播放来源保持居中；320px 下缩小右侧按钮以免挤出屏幕。两列仍保持原来的垂直居中布局。
- 队列可选歌播放、移除、清空，右键提供“从队列中移除”，不显示“添加到下一首”。队列保持原有排列，随机模式只控制实际切歌顺序，不重排界面；底栏与展开页的上一首 / 下一首共用 `prevNext`。直接展示完整队列，歌曲项使用 `content-visibility-auto` 延迟屏外渲染，不再提供“显示更多歌曲”；详见 [长列表优化](./styling.md#长列表使用-content-visibility-auto)。
- 队列顶部“定位当前歌曲”按钮将当前行滚动到列表中部，空队列时禁用；只滚动队列，不修改曲目、进度或播放状态。尊重减少动态效果设置，开启时直接定位。侧栏和浮窗共用 `QueueTracksApi.scrollToCurrent`，不通过全局 DOM 查询定位另一份队列。
- 展开 / 收起不操作 `Audio`，底栏和展开页共用 `client/composables/player.ts` 及 IndexedDB 缓存。音质切换保留进度与原播放 / 暂停状态；移除最后一首或清空队列时自动收起。

## 动画与交互约定

`ExpandedPlayer.tsx` 使用原生 `dialog.showModal()` / `close()`，浏览器负责背景 inert、焦点约束和焦点返回；Esc 或收起按钮更新同一个受控开关。空白区域按 Space 切换播放，按钮和滑块保留原生键盘行为。

`expanded-player.css` 负责全部开合动画：`@starting-style` 定义起点，`transform` / `opacity` 负责展开，`display` / `overlay` 的 `allow-discrete` 过渡保留完整退场。不要用条件渲染卸载对话框内容，也不要用定时器、逐帧 JS 或动画期间的布局测量替代它。`prefers-reduced-motion: reduce` 关闭过渡。不支持这些新 CSS 特性的浏览器仍可正常开关，只是动画会降级。原生机制参考 [MDN dialog 过渡](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog#animating_dialogs)。

共享组件：

- `PlaybackControls` / `PlaybackProgress` 同时用于底栏和展开页；进度手势保留同步局部变量，不能改成 Solid 2 写完立刻回读的 signal。
- `VolumeSlider` 的 `expanded` 形态填满容器；音质及播放重试动作集中在 `player-controls.ts`。
- 图标类名字面量放在 `.tsx` 中，确保 UnoCSS 默认扫描能提取。新增组件后需要实际检查开发与生产 CSS，不能仅凭类型检查判断样式已生成。

## 对话框内的浮层

`Popover`、`Tooltip` 和 `QualityBtn` 通过 `portalMount` 将浮层挂到所属 dialog 内。共享 `ContextMenuHost` 按当前来源的 `closest('dialog')` 自动选择 Portal 容器。**不能统一挂回 body**：模态对话框外的节点是 inert，菜单即使显示，也可能无法点击或获取焦点。

收起对话框前关闭其内部 Popover，避免浮层脱离界面残留；仅关闭右键菜单或音质菜单时，对话框继续保持打开。不要回退右键菜单的 `popover="manual"`，否则右键释放会触发原生自动关闭。

## 验证

类型检查、客户端测试及扩展构建后，在实际扩展中验证：

1. 播放时连续展开 / 收起，确认音频地址、进度、队列及音量保持，Esc 收起后焦点回到封面按钮。
2. 检查开场和退场动画，尤其关闭时内容没有提前消失；开启减少动态效果后无移动动画。
3. 操作进度、音量、模式和队列；测试播放中与暂停时的音质选择、错误重试，检查控制台。
4. 对话框内打开右键菜单、音质菜单，用鼠标和键盘选择；Esc 应先关闭菜单，再关闭展开页。
5. 在桌面、390px、320px 及矮窗口检查主界面和队列浮窗，无横向溢出，必要时内容区可纵向滚动。检查空队列自动收起、完整大队列首尾可达、当前歌曲定位及外层页面没有被滚动。

## 歌词

- Provider 可选 `getLyrics(id, { signal })`，返回 `LyricsInfo` 的原文、翻译、音译 LRC 和纯音乐标识；`wordByWord` 可提供逐字原文及对应时间轴的翻译、音译。网易云使用官方 `/api/song/lyric/v1` 对应 WEAPI 请求，同时获取 YRC 与普通 LRC，参数参考 [api-enhanced 的新版歌词实现](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/lyric_new.js)，没有引入其 Node.js 依赖。QQ 音乐现有接口返回普通 LRC 时沿用逐行高亮；BiliBili 暂无实现，显示「此音源暂不提供歌词」；曲目自带 `lrc` 时仍可展示。
- `createLyrics` 仅在展开或切歌时读取，最多缓存 100 首歌词到内存；不随时间更新请求或读写 IndexedDB。切歌、关闭或卸载会取消请求并忽略迟到结果；失败显示错误和重试，不能冒充无歌词。
- `client/utils/lyrics.ts` 解析多时间标签、毫秒、小数、offset（正值提前）、相同时刻多行和纯文本，并支持 YRC 与角括号时间标记的增强 LRC。YRC 行、字的起点均为绝对毫秒，忽略 JSON 元数据；offset 同时调整行与字。没有有效逐字数据时回退原始 LRC，混合时间轴中无有效字时间的行保留逐行高亮。翻译 / 音译使用相应时间轴按时间戳对齐。无时间轴的歌词只展示文本。
- 当前行的逐字高亮按字起点与持续时间，以文字渐变填充推进。只有逐字歌词正在播放且展开页可见时启动 `requestAnimationFrame`，每帧读取真实 `audio.currentTime`，不按墙钟累加时间；暂停、后台、收起或卸载会取消动画。暂停后跳转直接使用共享进度，快进、回退及倍速不会让动画继续漂移。普通 LRC 不启动逐帧更新；缺少末字结束标记的增强 LRC 在该字起点点亮，不估算不存在的字内时间。
- `Lyrics` 对播放时间二分定位，只有行号或布局变化时滚动内部容器，不滚动整个页面；手动滚动暂停跟随，「回到当前歌词」恢复。点击有效时间轴行只跳转进度，保留原播放 / 暂停状态，音源加载中禁止跳转。减少动态效果时直接定位。
- 移动端切换及跨断点尺寸变化通过 ResizeObserver 重新定位，返回清理函数释放观察器。只有实际布局需要的滚动定位使用 JS，歌词颜色和播放器动画仍由 CSS 完成。
- 歌词滚动区上下边缘使用渐变遮罩淡出，并叠加带渐变遮罩的 `backdrop-filter` 模糊层，中部保持清晰。边缘层不接收指针事件；「回到当前歌词」位于其上方，不受模糊影响。模糊不支持时仍保留遮罩淡出。

歌词验证：真实网易云 YRC、无逐字数据的逐行回退、纯音乐、无时间轴文本、快速切歌的迟到响应、失败重试、暂停 / 跳转 / 倒退时的字内进度、点击跳转、手动浏览恢复跟随、翻译开关，以及桌面 / 390px / 320px 布局。
