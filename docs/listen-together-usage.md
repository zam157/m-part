# 一起听使用与部署

一起听已接入正式播放器，入口为侧栏「一起听」（`/listen`）。默认使用成员独立取源：房间服务同步歌曲、队列与进度，每台设备使用自己的浏览器登录态获取音频。另提供网易云、QQ 音乐和 BiliBili 托管实验，服务启动即具备托管能力，无环境变量开关：房主选择服务器托管后，服务器按曲目平台使用该平台账号或匿名取源并转发音频，成员不接收账号凭据。当前协议版本为 **5**，升级时同时更新扩展 / Web、房间服务和实验工具；旧客户端会收到升级提示。

## 启动与使用

本机开发开两个终端：

```bash
pnpm dev:rooms   # 房间服务 http://127.0.0.1:3410
pnpm dev:ext     # 按日志加载 apps/extension/.output/chrome-mv3-dev
```

1. 房主打开侧栏「一起听」，填写服务器地址与称呼，点击「用当前队列创建」。当前歌曲和进度会带入房间，空队列也可创建。
2. 朋友使用同一个服务器地址，输入房主提供的 8 位房间码加入。首次自动播放受阻时，点击「恢复播放 / 恢复同步」。
3. 房主可在成员列表点击「设为管理员」，也可随时撤销。房主与管理员在原有首页、搜索、歌单、队列或展开播放器中操作即可；歌曲播放、队列增删、上一首 / 下一首、播放模式和跳转通过房间统一执行。
4. 普通成员可以调音量、切本机音质、暂停自己或恢复跟随。播放与队列控制会禁用；通过系统媒体按键等其他入口发出的越权操作也会被拦截。
5. 退出后恢复原来的个人队列、进度和播放模式，默认保持暂停。房主退出会结束房间，所有成员恢复个人状态。

`127.0.0.1` 只表示当前电脑。两台电脑上的 `127.0.0.1` 不是同一台服务器；跨设备使用需要双方都能访问的服务地址，支持 HTTP 和 HTTPS（分别连接 WS / WSS）。也可构建时通过 `VITE_ROOM_SERVER_URL=https://rooms.example.com` 设置默认地址，用户仍可在界面修改。设置只保存服务器地址，不含恢复凭据。

## 管理员与聊天记录

- 房主可在成员列表授予 / 撤销管理员。管理员可添加、移除和选择歌曲，更换队列，播放 / 暂停全员、跳转、切歌及切换播放模式；所有页面、快捷键和 Media Session 共用权限检查。撤销后客户端取消待发控制，服务器同样拦截越权指令。
- 结束房间、授予 / 撤销管理员、绑定 / 替换 / 撤销托管凭据、切换全房间来源及重试托管音源仍仅限房主。管理员退出只退出本人；房主离线宽限与结束规则不变，不自动转让房主；宽限期间可继续聊天，播放控制等待房主恢复。自然结束、权威媒体时长及全员缓冲仍以房主的媒体状态为准，避免多端重复切歌。
- 管理员身份随原成员恢复凭据保留；主动退出后重新加入是新身份，不继承权限。仅服务端记录决定角色，客户端不能自报管理员。
- 「聊天与动态」显示全部记录，也可筛选聊天或操作。聊天最多 500 字，Enter 发送、Shift + Enter 换行，输入法确认选词不会发送。每成员的消息与授权操作合计限 10 秒 8 次。聊天使用纯文本显示；作者与时间由服务器填写。失败保留输入，超时或断线不自动重发，先查看记录确认结果。
- 记录包括加入 / 重连 / 退出、授权变更、播放、暂停、跳转、切歌、队列 / 模式及托管来源操作。只记录已接受的操作，重复指令不重复记入；自动心跳、就绪与漂移校正不刷屏。托管操作只记录通用描述，不记录 Cookie、票据或上游地址。
- 当前房间内存保留最近 **200 条**聊天与操作记录，新加入和重连者都能查看；房间结束、过期或服务重启后不可恢复。列表高度固定，阅读旧记录时不会强制滚到底部，有新记录时可点击返回最新。
- 聊天与角色变更不推进播放 `revision`，也不重新准备音频；独立 `activityVersion` 防止迟到的 HTTP 快照覆盖较新的聊天和角色。客户端、服务端与实验工具必须一起升级到协议 5。


## 局域网 HTTP 测试

1. 两台电脑安装更新后的扩展（`pnpm build:ext` 产出的 `apps/extension/.output/chrome-mv3`）。开发构建也可使用，但修改 manifest 后需要重新加载扩展，才能申请 HTTP 主机的访问权限。
2. 在服务器电脑启动一个房间服务，不需要收集扩展 ID 或配置来源白名单：

   ```bash
   pnpm dev:rooms:lan
   ```

3. 假设服务器局域网 IP 为 `192.168.1.10`，另一台电脑先打开 `http://192.168.1.10:3410/health`，应返回 JSON。系统防火墙需允许该端口；两台设备应处于可互相访问的网络，访客 Wi-Fi 的设备隔离可能阻止连接。
4. 两端在「一起听」填写 `http://192.168.1.10:3410`，允许扩展访问该主机。房主创建后，朋友用房间码加入。不要填写 `0.0.0.0`（监听地址）或另一台电脑自己的 `127.0.0.1`。

HTTP 会明文传输房间状态和恢复令牌，适合可信局域网测试；公网建议 HTTPS。此步骤以扩展客户端为准，普通 HTTPS 网页连接 HTTP / WS 仍可能被浏览器的混合内容策略拦截。

通过回环、IPv4 私有地址（`10.*`、`172.16.*`–`172.31.*`、`192.168.*`）、链路本地地址或 IPv6 ULA 地址连接服务时，默认允许任意合法的 Chrome 扩展 ID 和服务同源网页。其他网页来源仍会被拒绝。如果之前导出了 `LISTEN_ALLOWED_ORIGINS`，先运行 `unset LISTEN_ALLOWED_ORIGINS`；显式设置的白名单（包括空值）会优先执行。使用自定义局域网域名时仍可显式配置允许来源。

不需要热更新时，可先 `pnpm build:rooms`，再运行 `HOST=0.0.0.0 PORT=3410 node apps/rooms/dist/server/index.mjs`。

## 当前能力与边界

| 项目 | 行为 |
| --- | --- |
| 房间 | 2–5 人私密小房间，也允许房主单人创建；最长 12 小时，单实例重启后失效 |
| 队列 | 最多 1000 首，按 Provider + ID 播放；队列由房主 / 管理员控制，随机选择与自动下一首由房主 / 服务端统一决定 |
| 音源 | 网易云、QQ 音乐、BiliBili 可独立取源；可显式启用三平台房间托管，三平台账号可共存，未绑定平台匿名取源。试听或无法确认完整播放能力的音源不跟随 |
| 内容差异 | 同时检查实际媒体时长与房间曲目时长；相差超过 `max(2 秒, 1%)` 时明确报错，不把片段当成完整时间轴 |
| 同步 | 校时、预约开始、实际媒体就绪 / 播放确认；偏差超过 300ms 时 seek，校正冷却 2 秒 |
| 暂离 | 成员主动暂停后不因切歌、跳转、刷新、重连或返回前台而自动开声，需主动恢复 |
| 缓冲 | 成员缓冲不暂停其他人；房主持续缓冲才暂停全房间，准备好后重新预约；手动暂停会取消自动恢复 |
| 系统控制 | Media Session 与页面共用房间意图入口；普通成员系统暂停只暂停本机，房主 / 管理员系统暂停同步全员 |
| 个人缓存 | 入房前完成保护性保存；房间队列和位置不写入个人缓存，音量仍是个人偏好 |
| 多窗口 | 同一来源、同一房间只允许一个窗口播放；第二窗口提示先退出或关闭原窗口，不抢占并重复出声 |

已有登录或会员并不保证朋友也有同样的播放权限。完整权限标记与时长检查能发现试听等常见问题，但不声称已证明不同编码的每个音频采样完全一致；首版不自动跨 Provider 匹配歌曲。

当前不包含平台官方一起听房间互通、跨 Provider 自动匹配、房主转移或关闭页面后的后台音频。这些是[设计文档](./listen-together.md)中的扩展方向，不影响当前独立模式使用。普通移动网页后台冻结仍受浏览器和系统限制，Media Session 不能保证 JavaScript 常驻。

## 断线与恢复

- 每 5 秒发送应用层心跳，12 秒没有有效服务端响应时重建连接，重连采用有上限的退避及随机抖动。
- 从最后服务端响应起失联 20 秒，本机暂停；恢复后校时、获取最新快照并重新追赶，不补放旧指令。
- 普通成员离线 20 秒后释放名额，身份仍可恢复 10 分钟；房间已满、房间结束或恢复凭据过期时明确提示重新加入。每个房间最多保留 50 个离线恢复记录，避免无限积累。
- 房主离线超过 20 秒宽限后结束房间，不自动转移房主。刷新在宽限内恢复原成员和房主身份，旧连接失去权限。
- 恢复凭据保存在当前标签页的 sessionStorage。主动退出会撤销；服务器重启使所有凭据失效。普通关闭后新建一个无会话的标签页需要重新加入。

## 生产服务部署

房间服务可与扩展独立部署，不需要同时运行网页代理。默认独立模式不需要第三方 Cookie；仅由房主显式绑定时才处理所选平台会话。使用支持 WebSocket 长连接的常驻 Node 服务：

```bash
pnpm install --frozen-lockfile
pnpm build:rooms

LISTEN_ALLOWED_ORIGINS='chrome-extension://EXTENSION_ID' \
  HOST=127.0.0.1 PORT=3410 node apps/rooms/dist/server/index.mjs
```

把 `EXTENSION_ID` 换成使用中的扩展 ID；开发目录与生产目录安装的 ID 可能不同。多个允许来源用逗号分隔；如果还提供网页前端，应加入该前端精确的 Origin（包含协议和非默认端口）。仅声明来源不能替代成员令牌校验，两者均由服务端检查。

公网建议在 Node 前配置 HTTPS / WSS 反向代理，将 `/ws` 的 WebSocket Upgrade 转发至该端口，并设置适合长连接的超时。用户统一填写如 `https://rooms.example.com` 的根地址，也允许 HTTP；不附路径、账号、查询参数或恢复令牌。`GET /health` 返回服务名、协议版本、默认取源模式和 `hostedEnabled: true` 托管能力标记，可用于健康检查。

默认本机及局域网 IP 接受服务同源页面与任意合法 Chrome 扩展来源；公网 IP 或域名需要显式设置 `LISTEN_ALLOWED_ORIGINS`。显式白名单在所有地址上都优先执行；不会因转发头声称内网地址而放宽来源限制。已有应用层连接、消息、队列、验证尝试和来源频率上限；反向代理还应限制连接 / 请求速率和报文大小，按服务器容量设置进程资源上限。当前为单实例内存房间，多实例部署需要房间归属和统一排序，不能直接启动多个不共享状态的实例做负载均衡。

扩展已声明本机服务器权限；用户连接自行填写的 HTTP / HTTPS 主机时，仅申请该协议和主机的可选权限。实际生成的扩展 CSP 未限制 `connect-src` / `media-src`，允许房间连接和现有音源。房间服务不使用音乐平台的 DNR 请求头规则；托管只接受房间曲目身份，不能提交上游 URL 或任意请求头，不是开放代理。

## 可选：网易云 / QQ 音乐 / BiliBili 房间托管实验

这项实验将所选平台会话交给你填写的服务器，必须使用自己信任的服务。不会自动读取或上传浏览器登录态；真实账号验证仅在用户明确授权并自行在页面提交凭据后进行。平台是否接受目标服务器的会话、地域 / 会员权限、并发和风控仍需在目标部署实测，不能将模拟上游验证当作平台验收。

### 开启和使用

本机调试（回环 HTTP 允许提交测试会话）：

```bash
pnpm dev:rooms
```

部署到 HTTPS 反向代理后方：

```bash
LISTEN_PUBLIC_ORIGIN='https://rooms.example.com' \
LISTEN_ALLOWED_ORIGINS='chrome-extension://EXTENSION_ID' \
NITRO_HOST=127.0.0.1 NITRO_PORT=3410 node apps/rooms/dist/server/index.mjs
```

`LISTEN_PUBLIC_ORIGIN` 必须是精确的 HTTPS Origin，不带末尾 `/` 或路径。它明确声明外层已终止 TLS，不信任任意转发头；此时 Node 应只监听回环并仅由可信反向代理访问。反向代理将 `/ws`、`/room-control` 和 `/room-audio` 都转到同一进程。直接 HTTPS 运行或本机回环调试不必设置它。服务启动后即可绑定托管账号，无需环境变量开关；新房间仍默认独立取源，不自动绑定或上传任何账号。

1. 更新服务与客户端后创建房间，展开「房间音源」，选择「全员使用服务器音源」。无需 Cookie 即可开启，未绑定的平台匿名请求；新房间仍默认各自取源。
2. 如需登录权限，由房主选择账号平台，再在密码输入框显式粘贴该平台登录 Cookie，点击「绑定所选平台账号」。三平台分别保存，绑定账号不会切换房间模式。仅提取下表中的受控字段，不会将其他 Cookie 转发给上游；提交后输入立即清空。远程绑定地址必须 HTTPS；局域网 HTTP 地址不允许提交第三方会话。局域网测试可由房主在服务电脑通过 `http://127.0.0.1:3410` 绑定，其余成员通过该电脑的私有 IP 加入并使用房间托管音源。
3. 验证通过后在对应平台行显示账号尾号；当前曲目显示「账号托管」或「匿名托管」。成员默认跟随房间来源。媒体由原生 Audio 流式加载，不下载完整 Blob。
4. 失败、试听、无版权、验证限制或当前歌曲的凭据失效会暂停房间，等待房主主动「重试房间音源」、重新绑定或切回「全员各自取源」。不密集重试，不暗中使用成员个人账号。混合队列按每首歌的平台取源：例如仅绑定网易云，QQ / BiliBili 使用匿名取源；也可同时绑定三个平台。账号失效仅影响对应平台，不会删除其他账号。当前平台重新绑定 / 撤销时废弃旧票据并中止旧媒体；操作其他平台账号不推进播放 revision，不打断当前歌曲。
5. 成员可显式「本机改用个人音源」，只影响自己的来源；会重新检查完整权限和时长，再追赶同一房间时间轴。主动暂离不会因换源被清除。全局错误已暂停房间时仍需房主恢复播放。
6. 房主可随时撤销某个平台账号。仅清除该平台的内存会话；若正在使用该平台，撤销旧媒体后按匿名权限重新准备，仍保持服务器托管。若匿名权限不足则提示登录 / 版权限制，不自动使用个人账号。房间结束或服务重启清除所有平台会话，不做会话落盘。已经缓冲到客户端的字节无法追回，客户端收到状态后会停音并清除托管媒体源。

### 各平台凭据与媒体策略

| 平台 | 受控 Cookie 字段 | 账号与音频检查 |
| --- | --- | --- |
| 网易云 | 必需 `MUSIC_U`；可选 `__csrf` | 账号接口验证，完整歌曲 URL；拒绝 `freeTrialInfo` |
| QQ 音乐 | `qqmusic_uin` / `uin` / `wxuin` + `qqmusic_key` / `qm_keyst` / `p_skey` / `skey`；可选 `eas_sid`、`login_type`、`tmeLoginType` | 通过登录专用 RPC 校验，建议从已登录网页复制包含 `eas_sid` 的完整 Cookie；song MID / media MID 与完整文件名匹配，依次选 MP3 320K / 128K / AAC |
| BiliBili | 必需 `SESSDATA`；可选 `bili_jct`、`DedeUserID`、`DedeUserID__ckMd5`、`buvid3`、`buvid4` | nav 登录及账号检查；view → WBI playurl，只选完整 AAC DASH 音轨；拒绝试看和时长不符 |

QQ 的登录检查使用 `music.UserInfo.userInfoServer.GetLoginUserInfo`，不以公开用户资料接口代替登录验证。RPC 结构参考[接口源码](https://github.com/chongya369/qqmusic-api-py/blob/main/qqmusic/apis/user.py)，只调用平台 API，不引入该项目运行时代码。QQ CDN 仅添加固定 Referer；BiliBili CDN 仅添加固定 Referer / User-Agent，均不携带 API Cookie。BiliBili 允许 DASH 音轨的 MP4 MIME，仍不解析或转发视频轨；海外其他 CDN 暂未加入白名单。

### 媒体租约、Range 与资源上限

- `/room-control` 使用现有成员恢复令牌作 Bearer 鉴权，显式 `credentials: 'omit'`；管理操作还校验房主及控制版本。Cookie 只发对应平台固定 API，不发 CDN、成员或 WebSocket。
- `/room-audio?ticket=…` 使用随机短期票据，绑定成员、连接代次、房间、音源版本和播放实例。租约 120 秒，客户端约 60 秒续期而不更换 Audio URL；退出、重连换代、换歌、模式切换、撤销与结束使旧票据失效。每次 Range 仍重新鉴权。暂停仍续租，主动暂离后过期则在恢复时重新申请。
- 公开队列、广播、个人缓存不含票据或上游地址。只合并同一房间当前音源的解析，不缓存音频字节，不假定合并解析就减少每个成员的上游下载。
- 每个平台使用独立 CDN 白名单，逐次检查重定向；网易云仅 `*.music.126.net`，QQ 仅 `stream.qqmusic.qq.com` 及其子域、`aqqmusic.tc.qq.com`，BiliBili 仅 `bilivideo.com` / `bilivideo.cn` 及其子域，不允许任意 Akamai 域；支持单段 / 尾部 / 开放尾部 Range、`206` 与 `416`，检查范围和字节长度。上游忽略 Range 时保留 `200` 并取消范围能力，不伪造 `206`。
- 单次媒体请求遇到上游签名地址到期后最多重新解析一次；只有 Provider 确认文件 MD5 及大小一致，才继续原票据的范围请求。变化或无法确认时暂停，等房主主动重试生成新音源版本，不拼接不同文件。QQ / Bili 当前没有可信的文件 MD5 与大小，地址过期后需房主主动重试，不继续原票据拼接。
- 单响应最多 64 MiB；并发上限为全局 40、每房间当前资源 10、每票据 2；响应最长 30 分钟，上游响应头超时 15 秒。分钟流量上限每房间 128 MiB、全局 512 MiB；另有成员操作频率、票据数量及 HTTP 管理入口限制。服务默认不记录请求体、凭据、票据或上游地址。

### 反向代理日志

票据是短期媒体访问权限，不能写入访问日志。代理和监控对 `/room-audio` 应关闭访问日志，或只记不含查询串的路径；`/room-control` 不记录请求体、Authorization 或调试转储。不要用 `$request_uri` / 原始请求行保留媒体查询参数。Nginx 可在既有转发配置中增加：

```nginx
location = /room-audio {
    access_log off;
    proxy_pass http://127.0.0.1:3410;
    proxy_buffering off;
    proxy_read_timeout 1800s;
}
```

还需检查外层 CDN、负载均衡及错误日志的 URL 采集规则。音频带宽、连接数和目标平台会话行为在目标部署单独压测；当前没有跨地域 / 公网真实平台托管验收数据。
