# 一起听使用与部署

一起听已接入正式播放器，入口为侧栏「一起听」（`/listen`）。当前交付的是成员独立取源模式：房间服务同步歌曲、队列与进度，每台设备使用自己的浏览器登录态获取音频。房间不共享第三方账号，也不转发第三方音频。

## 启动与使用

本机开发开两个终端：

```bash
pnpm dev:rooms   # 房间服务 http://127.0.0.1:3410
pnpm dev:ext     # 按日志加载 .output/chrome-mv3-dev
```

1. 房主打开侧栏「一起听」，填写服务器地址与称呼，点击「用当前队列创建」。当前歌曲和进度会带入房间，空队列也可创建。
2. 朋友使用同一个服务器地址，输入房主提供的 8 位房间码加入。首次自动播放受阻时，点击「恢复播放 / 恢复同步」。
3. 房主在原有首页、搜索、歌单、队列或展开播放器中操作即可；歌曲播放、队列增删、上一首 / 下一首、播放模式和跳转通过房间统一执行。
4. 成员可以调音量、切本机音质、暂停自己或恢复跟随。房主专属操作会禁用；通过系统媒体按键等其他入口发出的越权操作也会被拦截。
5. 退出后恢复原来的个人队列、进度和播放模式，默认保持暂停。房主退出会结束房间，所有成员恢复个人状态。

`127.0.0.1` 只表示当前电脑。两台电脑上的 `127.0.0.1` 不是同一台服务器；跨设备使用需要双方都能访问的服务地址，支持 HTTP 和 HTTPS（分别连接 WS / WSS）。也可构建时通过 `VITE_ROOM_SERVER_URL=https://rooms.example.com` 设置默认地址，用户仍可在界面修改。设置只保存服务器地址，不含恢复凭据。

## 局域网 HTTP 测试

1. 两台电脑安装更新后的扩展（`pnpm build:ext` 产出的 `.output/chrome-mv3`），并从各自的 `chrome://extensions` 复制扩展 ID。开发构建也可使用，但修改 manifest 后需要重新加载扩展，才能申请 HTTP 主机的访问权限。
2. 在服务器电脑启动一个房间服务，将两端的扩展 Origin 都加入白名单；相同 ID 只填一次：

   ```bash
   LISTEN_ALLOWED_ORIGINS='chrome-extension://HOST_EXTENSION_ID,chrome-extension://MEMBER_EXTENSION_ID' \
     pnpm dev:rooms:lan
   ```

3. 假设服务器局域网 IP 为 `192.168.1.10`，另一台电脑先打开 `http://192.168.1.10:3410/health`，应返回 JSON。系统防火墙需允许该端口；两台设备应处于可互相访问的网络，访客 Wi-Fi 的设备隔离可能阻止连接。
4. 两端在「一起听」填写 `http://192.168.1.10:3410`，允许扩展访问该主机。房主创建后，朋友用房间码加入。不要填写 `0.0.0.0`（监听地址）或另一台电脑自己的 `127.0.0.1`。

HTTP 会明文传输房间状态和恢复令牌，适合可信局域网测试；公网建议 HTTPS。此步骤以扩展客户端为准，普通 HTTPS 网页连接 HTTP / WS 仍可能被浏览器的混合内容策略拦截。

不需要热更新时，可先 `pnpm build:rooms`，再使用同一份 `LISTEN_ALLOWED_ORIGINS` 设置运行 `HOST=0.0.0.0 PORT=3410 node dist/rooms/server/index.mjs`。

## 当前能力与边界

| 项目 | 行为 |
| --- | --- |
| 房间 | 2–5 人私密小房间，也允许房主单人创建；最长 12 小时，单实例重启后失效 |
| 队列 | 最多 1000 首，按 Provider + ID 播放；队列、随机选择和自动下一首由房主 / 服务端统一决定 |
| 音源 | 网易云、QQ 音乐、BiliBili 通过现有 Provider 独立取源；显式标记试听或无法确认完整播放能力的音源不跟随 |
| 内容差异 | 同时检查实际媒体时长与房间曲目时长；相差超过 `max(2 秒, 1%)` 时明确报错，不把片段当成完整时间轴 |
| 同步 | 校时、预约开始、实际媒体就绪 / 播放确认；偏差超过 300ms 时 seek，校正冷却 2 秒 |
| 暂离 | 成员主动暂停后不因切歌、跳转、刷新、重连或返回前台而自动开声，需主动恢复 |
| 缓冲 | 成员缓冲不暂停其他人；房主持续缓冲才暂停全房间，准备好后重新预约；手动暂停会取消自动恢复 |
| 系统控制 | Media Session 与页面共用房间意图入口；成员系统暂停只暂停本机，房主系统暂停同步全员 |
| 个人缓存 | 入房前完成保护性保存；房间队列和位置不写入个人缓存，音量仍是个人偏好 |
| 多窗口 | 同一来源、同一房间只允许一个窗口播放；第二窗口提示先退出或关闭原窗口，不抢占并重复出声 |

已有登录或会员并不保证朋友也有同样的播放权限。完整权限标记与时长检查能发现试听等常见问题，但不声称已证明不同编码的每个音频采样完全一致；首版不自动跨 Provider 匹配歌曲。

当前不包含托管第三方凭据 / 音频代理、平台官方一起听房间互通、聊天、房主转移或关闭页面后的后台音频。这些是[设计文档](./listen-together.md)中的扩展方向，不影响当前独立模式使用。普通移动网页后台冻结仍受浏览器和系统限制，Media Session 不能保证 JavaScript 常驻。

## 断线与恢复

- 每 5 秒发送应用层心跳，12 秒没有有效服务端响应时重建连接，重连采用有上限的退避及随机抖动。
- 从最后服务端响应起失联 20 秒，本机暂停；恢复后校时、获取最新快照并重新追赶，不补放旧指令。
- 普通成员离线 20 秒后释放名额，身份仍可恢复 10 分钟；房间已满、房间结束或恢复凭据过期时明确提示重新加入。每个房间最多保留 50 个离线恢复记录，避免无限积累。
- 房主离线超过 20 秒宽限后结束房间，不自动转移房主。刷新在宽限内恢复原成员和房主身份，旧连接失去权限。
- 恢复凭据保存在当前标签页的 sessionStorage。主动退出会撤销；服务器重启使所有凭据失效。普通关闭后新建一个无会话的标签页需要重新加入。

## 生产服务部署

房间服务可与扩展独立部署，不需要恢复原有网页代理，也不需要第三方 Cookie。使用支持 WebSocket 长连接的常驻 Node 服务：

```bash
pnpm install --frozen-lockfile
pnpm build:rooms

LISTEN_ALLOWED_ORIGINS='chrome-extension://EXTENSION_ID' \
  HOST=127.0.0.1 PORT=3410 node dist/rooms/server/index.mjs
```

把 `EXTENSION_ID` 换成使用中的扩展 ID；开发目录与生产目录安装的 ID 可能不同。多个允许来源用逗号分隔；如果还提供网页前端，应加入该前端精确的 Origin（包含协议和非默认端口）。仅声明来源不能替代成员令牌校验，两者均由服务端检查。

公网建议在 Node 前配置 HTTPS / WSS 反向代理，将 `/ws` 的 WebSocket Upgrade 转发至该端口，并设置适合长连接的超时。用户统一填写如 `https://rooms.example.com` 的根地址，也允许 HTTP；不附路径、账号、查询参数或恢复令牌。`GET /health` 返回服务名、协议版本和独立取源模式，可用于健康检查。

默认本机开发只接受本机同源页面及 Chrome 扩展来源；公网环境显式设置 `LISTEN_ALLOWED_ORIGINS`。已有应用层连接、消息、队列、验证尝试和来源频率上限；反向代理还应限制连接 / 请求速率和报文大小，按服务器容量设置进程资源上限。当前为单实例内存房间，多实例部署需要房间归属和统一排序，不能直接启动多个不共享状态的实例做负载均衡。

扩展已声明本机服务器权限；用户连接自行填写的 HTTP / HTTPS 主机时，仅申请该协议和主机的可选权限。实际生成的扩展 CSP 未限制 `connect-src` / `media-src`，允许房间连接和现有音源。房间服务从不使用音乐平台的 DNR 请求头规则，也没有接收上游任意 URL 的媒体代理。

## 代码入口与验证

- `client/composables/player-context.ts`：所有播放器用户操作的房间拦截入口及可写状态；不要从组件绕过它直接控制音频。
- `client/composables/listen-room.ts`：模块级 UI 状态、连接、保护性保存、退出恢复及窗口会话。
- `client/utils/listen-client.ts`：连接 / 重连、校时、指令串行、来源准备、缓冲与漂移恢复。
- `client/utils/listen-media.ts`：可取消且有超时的媒体准备与播放结果。
- `server/utils/listen-rooms.ts`：权威时间轴、队列、角色、身份与指令去重。
- `shared/types/listen-room.ts`：双向严格校验的公开协议；禁止添加音频地址、Cookie 或第三方请求头。
- `services/rooms/nitro.config.ts`：正式独立服务配置；`experiments/listen-together/` 保留静态音频实验及测量工具。

```bash
pnpm typecheck
pnpm test:listen
pnpm exec vitest run --project client
pnpm build:rooms
pnpm build:ext
```

自动测试覆盖个人缓存隔离、所有控制入口、试听 / 时长差异、过期取源取消、指令排序及去重、主从权限、缓冲后手动暂停、恢复身份、长断线释放名额与旧连接失效。首次静态实验的精度数据仍见[实验记录](./listen-together-lab.md)，不能把它当作公网真实音源精度承诺。

2026-10-23 实测：使用开发与生产两个独立扩展实例，各自向网易云取源，播放「和小葛去石家庄」「Good Morning, NY」，验证加入追赶、队列替换、房主跳转和暂停、自然结束统一下一首。成员断网 22 秒后暂停，恢复网络后自动回到原房间并同步；主动暂离经过刷新及房主恢复播放仍保持暂停；同一来源的第二个窗口被拒绝且原窗口不受影响。320px 窄屏没有横向溢出。结束房间后，原 3 首个人队列、随机模式、原进度与音量均恢复，数据库个人记录未被房间的 2 首队列覆盖。
