# 播放器本地缓存

`client/main.tsx` 启动 `startPlayerPersistence()`。缓存使用浏览器原生 IndexedDB，不经过 Provider、服务端或 `localStorage`，也不需要额外扩展权限。开发热更新时会清理观察者、定时器和监听器。

## 存储与读写频率

数据库 `mpart-player`，版本 1，object store 为 `state`，包含三个独立记录：

| key | 内容 | 常规保存方式 |
| --- | --- | --- |
| `queue` | 曲目资料、播放模式、随机播放顺序 | 只在队列或模式变化时保存，200ms 合并 |
| `position` | 当前歌曲的 `provider + id`、秒数进度 | 连续进度变化 5 秒合并一次；切歌时与队列在同一事务中保存 |
| `volume` | 0–1 音量 | 连续调整 500ms 合并一次 |

启动只用一个只读事务获取这些记录，之后由内存信号驱动界面，不为每次变化读取数据库。高频更新使用固定时间窗口，持续拖动不会无限延迟保存；同一时间最多一个写事务，在途写入期间只保留待写的最新值。进度和音量的变化不会重复序列化、写入整个大队列。

暂停、进度调整完成、页面变为隐藏及 `pagehide` 时，等待信号提交后补存仍未写入的变化；没有变化时不创建写事务。主要保障来自播放期间的周期保存，不能依赖关闭页面时的异步写入一定完成，见 [MDN IndexedDB 生命周期说明](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)。异常退出后可能恢复到最近一次已完成的保存点。

写入失败会保留最新脏数据，延迟重试；缓存不可用不会阻止播放。队列与对应当前位置的更新在同一事务提交，避免部分成功。数据库升级通知会关闭旧连接。

## 恢复行为

- 恢复队列、当前歌曲、进度、音量、播放模式和有效的随机顺序，保持暂停。
- 仅缓存曲目资料，不缓存 `src`、临时音频 URL、音质 URL 或音频文件。首次点击播放时由 Provider 获取新 URL，在 `loadedmetadata` 后跳转到保存位置；加载期间忽略将进度归零的旧媒体事件。
- 缓存进度超出实际音频时长时，限制在有效范围内；缓存曲目身份无效时回到队列第一首。异常数据、重复曲目和无效随机索引会校正或过滤。
- IndexedDB 读取尚未完成时，用户已设置的音量、队列或进度优先，迟到缓存不能覆盖；启动恢复本身不会触发多余的回写。
- 恢复播放期间暂停或换歌会取消旧的播放意图，迟到音源响应不能自动开始播放。

扩展和普通网页按各自 origin 存储，同一扩展 ID 的开发 / 生产页共享 origin。此功能保存本地播放会话，不会修改平台歌单。

## 验证

客户端测试覆盖数据校验、临时 URL 排除、限频合并、慢事务串行化、失败重试、启动恢复与操作竞争、元数据就绪后跳转、恢复期间暂停等。

在实际扩展中加入多首歌曲，调整音量、模式和进度后暂停，刷新应用页：队列、歌曲、模式、音量及位置应恢复且不自动播放；点击播放应从保存位置继续。再测试删除 / 清空队列后的刷新、连续拖动音量、正常播放时的周期保存，并检查控制台。

实际验证：刷新恢复两首队列、随机模式、37% 音量和 34.5 秒位置；启动仅一个读取事务且不回写、不请求音频，点击播放从 34.5 秒继续。60 次连续音量调整合并为一次 `volume` 写入，没有额外读取或队列重写。
