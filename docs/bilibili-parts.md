# BiliBili 分 P 播放

点击首页、搜索、歌单或专辑里的 BiliBili 视频时先读取官方视频详情：单 P 直接播放，多 P 打开共享选择器。可搜索标题 / P 序号、点击播放一个 P，或勾选多个后「播放所选」「加入队列」；从下一首菜单进入时可将所选 P 依次插到当前曲目之后。全选不代表自动入队，关闭或 Escape 不改动队列。播放器上的「分 P」按钮及曲目菜单可重新打开选择器。

普通播放与一起听使用同一入口。房间内仍要求房主 / 管理员权限；选择期间退出或更换房间，旧选择不会被提交到新播放环境。批量添加通过协议 **6** 的 `append-many` 一次提交，按曲目标识去重、原子检查 1000 首上限，追加时保留当前音频；播放所选时只切换一次。

## 身份与接口

- 曲目 ID 为 `BV号:CID`，同一视频不同 P 可同时入队、分别恢复进度。P 序号仅用于显示，重排后仍按 CID 选择；已删除或不属于该 BV 的 CID 明确报错，不能自动回退到 P1。
- `GET /x/web-interface/view?bvid=...` 返回 `pages[]`，每项取 `cid`、`page`、`part`、`duration`。曲目标题显示 P 序号与分 P 标题，时长使用该 P 的秒数。
- `GET /x/player/wbi/playurl` 传入原始 `bvid` 和选定 `cid`，`timelength` 为该 P 的毫秒时长，不能与视频总 `duration` 比较。浏览器和托管适配器均校验单 P 时长及试看标记，托管继续只选完整 AAC 音轨及允许的 CDN。
- 托管视频详情响应上限单独设为 1MiB，分 P 数最多 1000；nav / playurl 等其他 JSON 仍限制 128KiB。实测 716P 详情约 160KB，原统一 128KiB 上限会错误拒绝。
- WBI key 从图片文件名去掉扩展名后提取；浏览器缓存改用 `wbi_info:v2`，不复用旧格式 key。

## 旧队列

只有 BV 号的旧条目仍解析为 P1。普通模式成功取源后将队列资料更正为 P1 的 CID、标题与时长，保存时不含媒体 URL。创建房间或批量播放整张歌单时，不会自动把每个视频展开成所有 P：旧视频条目先以未知时长进入房间，由房主实际媒体就绪后建立 P1 的时间轴；成员保留服务广播的权威时长。需要其他 P 时使用选择器明确加入。

实现分别在 `packages/music/src/utils/providers/bilibili-parts.ts`（纯身份 / 元数据）、`bilibili.ts`（浏览器 Provider）、`packages/player/src/composables/bili-parts.ts` 和 `components/BiliPartPicker/`（选择流程），以及 `apps/rooms/server/providers/bilibili.ts`（服务器取源）。

## 验证记录（2026-10-24）

507 项自动测试、完整 workspace 类型检查及 Web / 扩展 / rooms / lab 构建通过。覆盖 CID 选择与重排、删除分 P 拒绝、单 P 时长、响应大小限制、选择取消 / 重试 / 迟到响应、批量去重 / 权限 / 容量原子校验及追加不重载音频。

真实视频 `BV1Kb411W75N`（716P）在开发扩展中先打开选择器，选 P2 后普通播放使用 CID `84319446`、原生时长约 1024.28 秒；没有误用 P1 或 530118 秒的视频总时长。未绑定 Cookie 的真实 Nitro 服务与开发 / 生产两个独立扩展实例验证 P2 匿名托管播放、P1 切换，以及批量加入 P1 / P3 / P4。播放 P2 时追加 P4，原生音频进度继续增加，play / pause / load 次数均不变。成员刷新后恢复房间与正确的 P1 标题、时长及队列。390×844 视口下选择器完整显示且无横向溢出；侧栏、主题、Tooltip 与跨断点操作未出现 Solid 响应式 / 清理警告。

本机托管测试期间多次遇到 CDN 响应中途截断 / socket 断开，日志记录 `UND_ERR_RES_CONTENT_LENGTH_MISMATCH` 或 `UND_ERR_SOCKET` 及预期 / 实收字节数，服务按现有策略暂停房间；重新准备或切换曲目后可再次播放。这次验证确认分 P 选择与取源身份正确，不代表 CDN 长时间传输稳定、Bili 登录账号或公网双设备同步已验收。
