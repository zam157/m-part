# 歌曲下载

音乐卡片、搜索 / 歌单等歌曲列表及播放队列的右键菜单提供「下载歌曲」，键盘也可用 Shift+F10 打开。下载使用当前设备的 Provider 与浏览器登录态，获取默认可用音质，不切歌、不改变队列，也不调用一起听控制接口。房间普通成员同样可用；不使用房主的托管账号、音频地址或成员票据。

有分段能力的 Provider 共用 `TrackPartPicker`：未解析条目先查询，单段直接下载，多段选择一项或多项；已经解析的独立曲目直接下载。下载模式仅显示下载操作，不提供播放 / 加入队列，也不需要房间控制权限。分段能力约定见 [通用分段选择](./track-parts.md)。

文件名使用「歌曲标题 - 创作者」，清理路径分隔符和控制字符；取源返回规范化曲目信息时优先使用。实际容器签名优先于 Content-Type 和 URL 后缀，BiliBili `.m4s` 的 MP4 音轨保存为 `.m4a`，不把文件转码或改名伪装成 MP3；Provider 标记的试听文件名附带「试听」。不新增标签封装或音质选择界面。

进度和错误复用播放器通知浮层，不占页面布局；支持取消和失败重试，一次执行一组任务，防止连续点击重复请求。多个分段按源顺序逐个读取并提交保存，失败后重试当前失败项，不重复已提交文件。浏览器可能要求允许连续下载多个文件，最终是否保存以浏览器下载列表为准。

## 实现边界

- `composables/download.ts`：下载任务、重复操作保护、取消、分段选择与通知；不依赖播放器媒体或一起听取源状态。
- `utils/music-download.ts`：调用 Provider `getSourceInfo` 与统一 `tRequest`，保留取源 headers / 登录传输策略；拒绝 HTTP 错误、空文件、HTML / JSON 与不完整 Range 响应。
- 下载是显式的文件保存，会完整读取单个音频 Blob，再通过本地 Object URL 交给浏览器；交接后延迟回收 URL。扩展无需新增 downloads 权限，Web 沿用现有跨域 / 代理能力。此流程独立于播放，不能把播放器的原生 Audio 改为等待整个下载完成。
- 下载过程中关闭应用页会取消页面请求；文件一旦提交浏览器后，再关闭通知或取消剩余任务不会删除已提交文件。未提供可用音源或网络被拒绝时保留可重试错误，不自动切换平台或借用服务器凭据。
