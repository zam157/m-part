# 一起听：第一阶段同步实验

实现日期：2026-10-23。按[可行性与设计文档](./listen-together.md)的验证顺序，先实现独立的同步 / 恢复实验。这里不是正式的一起听入口，不接入第三方音乐账号，不读写个人播放器缓存。

后续进度：独立模式已进入正式播放器，入口和运行命令见[一起听使用说明](./listen-together-usage.md)。本文保留首次实验的数据与当时的范围，后续功能以正式说明为准。

## 运行

```bash
pnpm dev:listen
```

打开 `http://127.0.0.1:3400`，在两个独立窗口中分别创建和加入房间。房间码只显示在连接状态中。Chrome 首次拒绝自动播放时点击「恢复 / 允许播放」。

客户端先由独立 Vite 配置构建，再由 Nitro 开发服务提供页面及 WebSocket。修改实验客户端后需重新执行命令；服务端源码由 Nitro 监听。与 `pnpm dev:ext` 独立运行，不改变原有扩展入口。

生产构建及本机验证：

```bash
pnpm build:listen
PORT=3400 HOST=127.0.0.1 node apps/rooms/dist-lab/server/index.mjs

pnpm typecheck:listen
pnpm test:listen
```

实验使用单进程内存状态；重启使房间和恢复凭据失效，房间最长 30 分钟、最多 5 人。当前是本机实验服务，尚未完成公网部署验收。来源校验与正式服务共用：默认本机 / 局域网允许服务同源和合法 Chrome 扩展来源，拒绝缺少或不匹配的 Origin；公网部署需显式配置 `LISTEN_ALLOWED_ORIGINS`，并配置反向代理限流与资源管理，不能直接将实验端口对外开放当作正式产品。

## 已实现边界

- 使用项目生成的 90 秒单声道 PCM 节拍音频；不涉及外部版权素材。固定资源支持单段 Range、尾部范围、`206` 和 `416`，没有通用音频代理。
- WebSocket 首条消息创建 / 加入 / 恢复身份，恢复令牌只返回给本人；成员快照不含令牌。消息使用 Valibot 严格校验，限制大小、频率、连接和房间数量。
- 控制版本与播放实例独立，成员就绪 / 心跳不推进控制版本。服务端统一排序，指令按成员去重；拒绝过期或越权操作，客户端不重放重连前的未确认指令。
- 多次 RTT 校时、单调时钟、预约开始、可取消且有超时的媒体准备、播放结果确认。媒体准备检查元数据、数据可用及 seek 完成，不把赋值 `src` 当作就绪。
- 使用可调阈值硬 seek；默认偏差超过 300ms、距上次校正至少 2 秒时重新准备并追赶。尚未比较倍速微调的听感收益。
- 成员主动暂离、房主缓冲暂停与恢复、手动暂停取消自动恢复、启动受阻后主动恢复。模拟按钮用于复现这些状态，普通媒体 `waiting` 使用 500ms 确认窗口。
- 5 秒心跳、12 秒响应超时、20 秒失联本机暂停，重连使用退避与抖动。房主超出恢复宽限后结束房间，不转移权限。客户端主动断开时，服务端从收到关闭起计算房主恢复宽限；静默断网从最后有效消息计算。
- 同一页面刷新从 sessionStorage 恢复成员身份及主动暂离意图。重连提升连接代次、关闭旧连接；旧连接事件不影响新连接。实验页面被接管后立即停音且不自动重连。
- 遥测导出保留全体状态样本及事件，不导出恢复令牌。原始窗口数据分别导出，避免用两次工具读取的不同时间点直接计算进度差。

## 测量

两端各点击「导出测量 JSON」，再运行：

```bash
node apps/rooms/lab/analyze.ts host.json member.json
```

分析器将相同控制版本、相同播放实例的稳态配对样本换算到同一校准时刻，输出双端差值 P50 / P95、校时不确定性、配对覆盖率和各状态采样数 / 估计时长。稳态定义为已成功播放且最近一次准备 / 状态转换后经过至少 2 秒；配对样本时刻间隔不超过 750ms，同一对端样本最多使用一次。

恢复统计要求连续 3 次跟随样本的目标偏差均在 300ms 内；未观察到成功、被新控制取消或测量窗口不足时保留 `null`，不得只报告成功。客户端约每 500ms 采样，后台定时器可能降低实际频率，导出包含实际时间戳。页面上单端的目标误差 P95 不能当作双端差值。

### 本次本机结果

环境：同一台 macOS、Chrome 的两个隔离浏览器上下文、`127.0.0.1` 回环网络、固定 PCM 测试音频、阈值 seek 策略；未注入网络抖动。两端原始记录分别约 68.0 秒 / 61.5 秒，包含开始播放前的等待。

| 项目 | 结果 |
| --- | --- |
| 原始采样数 | 房主 110，成员 101 |
| 稳态配对样本 | 59，约占较短记录样本数的 58.4% |
| 双端媒体时间差 P50 / P95 / 最大值 | 21.23 / 21.45 / 21.83ms |
| 配对校时不确定性之和 P95 | 约 0.70ms |
| 播放区间 | 房主约 38.0 秒，成员约 43.5 秒 |
| 本次漂移校正 seek | 双端均为 0 |
| 房主播放指令至连续三次误差达标 | 约 2.16 秒（含预约等待及采样确认） |

这只是对当前同步模型的本机验证，不能推断公网、两台物理设备、移动后台或扬声器出声同步。真实设备、延迟 / 丢包 / 抖动条件下的测量和倍速策略对比仍待完成。

浏览器另行验证：成员主动暂离后经过房主 seek、成员刷新仍保持暂停；主动恢复可重新跟随；房主模拟缓冲可暂停并重新预约播放；缓冲期间手动暂停阻止自动恢复；模拟启动受阻冻结时间轴，再次主动播放可恢复；房主刷新保留身份，断开重连提升连接代次；测试资源 Range / 无效范围响应正确。受阻实验曾发现重复状态反馈推进版本的问题，已增加「仅存在播放意图时才冻结」的处理和回归断言，并复测版本保持稳定。

自动验证：实验用例 35 个通过，既有客户端用例 215 个通过；实验、前端、后端及构建配置类型检查通过；实验生产构建与扩展构建通过。实验测试包含媒体准备 / 播放启动超时、取消、主动暂离、身份接管、过期通知、指令重复 / 冲突、播放结束后重新开始及缓冲后手动暂停等行为。

## 首次实验后的进度

以下是首次实验时的计划，现已由正式播放器和网易云托管实验完成相应代码接入；真实目标服务器 / 双物理设备量化测试仍独立验收：

1. 抽出可复用的传输 / 同步控制，接入现有播放器，先完成个人缓存与房间会话隔离。
2. 统一页面、队列、快捷键、音质切换及 Media Session 的控制入口，完善真实取源的取消与明确结果。
3. 接一个真实 Provider，确认完整时间轴、试听 / 无权限和失败状态；托管取源另做服务器会话、鉴权媒体票据、Range 转发与撤销实验。
4. 补齐正式房间界面、本机多窗口音频互斥、公网限流 / 身份管理及双物理设备测试。服务端连接代次本身不等于完整的本机多窗口互斥。

## 倍速策略对比工具（2026-10-23 补充）

页面新增「校正策略」选择：默认仍是「阈值 seek」，可选「有限倍速微调（实验）」。该选择只作用于实验页，不改变正式播放器。

| 策略 | 行为 |
| --- | --- |
| seek | 默认误差超过 300ms 时硬校正，阈值可调，冷却 2 秒 |
| rate | 误差超过 150ms 才启动 ±2% 微调；领先用 0.98，落后用 1.02；回到 80ms 内恢复 1；超过 500ms 或微调持续 15 秒则 seek，seek 冷却 2 秒 |

暂停、缓冲、切歌、跳转、暂离、断线、恢复前台、退出及切换策略都取消旧校正并恢复 1 倍速。微调不改变共享时间轴，不作为房主改速广播。

导出的样本补充 `playbackRate` 和 `strategy`，分析器按样本实际倍速外推位置，输出 `rateCorrectionMs` 与 `hardSeeksPerMinute`。旧测量文件缺少这些字段时按 1 倍速处理；每分钟 seek 以测量首尾窗口归一化，不能把本次短窗口直接当作一分钟总数。

对比时使用相同音频、设备、网络条件和操作顺序，分别导出 seek / rate 两组双端记录，报告 P50 / P95、恢复耗时、异常占比、每分钟 seek、倍速持续时长及听感。上方首次实验数据仍是 seek 结果，没有新做双物理设备、延迟 / 丢包 / 抖动及听感对比，不据此调整生产默认策略。

本次浏览器另验证 rate 策略在手工引入约 350ms 领先后降到 0.98，模拟缓冲立即恢复 1 倍速并暂停。这是策略功能检查，没有形成新的双端精度测量结论。
